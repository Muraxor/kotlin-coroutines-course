# Результаты: async и композиция

**Источник:** [официальная документация Kotlin / JetBrains](https://kotlinlang.org/docs/composing-suspending-functions.html). Ниже — выборочный учебный перевод и объяснение ключевых положений главы, а не полный текст документации. Примеры адаптированы для задач этого проекта. Чтобы сверить детали поведения, перейди по ссылкам у каждого раздела.

## Последовательность по умолчанию

Два обычных вызова suspend-функций выполняются последовательно. Если каждая ждёт 200 мс, общий путь займёт около 400 мс. Это правильно, когда второй вызов зависит от результата первого. Перед параллелизацией нарисуй зависимости: что можно начинать без других ответов?

[Официальный раздел](https://kotlinlang.org/docs/composing-suspending-functions.html#sequential-by-default).

## async и Deferred

async создаёт корутину с результатом типа Deferred<T>. await получает значение или передаёт ошибку, при необходимости приостанавливаясь. В отличие от launch, у async есть бизнес-результат. Создай оба Deferred до первого await, если операции независимы; немедленный await после каждого async снова сделает путь последовательным.

[Официальный раздел](https://kotlinlang.org/docs/composing-suspending-functions.html#concurrent-using-async).

## Структурированная композиция

Оборачивай группу async в coroutineScope и возвращай итог из неё. Если одна обычная дочерняя задача падает, scope отменяет остальных и отдаёт ошибку наружу. Это позволяет вызывающему коду считать возврат функции точной границей завершения всей загрузки. Не создавай новый произвольный CoroutineScope внутри такой функции.

[Официальный раздел](https://kotlinlang.org/docs/composing-suspending-functions.html#structured-concurrency-with-async).

## Порядок результатов и измерение

awaitAll возвращает список результатов в порядке переданных Deferred, даже если дети завершились иначе. Записи в журнале помогут увидеть фактическое расписание, но порядок завершения не должен быть частью контракта, если задача этого не требует. В учебном сравнении замеряй одинаковые операции в последовательной и конкурентной версиях; миллисекунды могут колебаться.

[Официальный раздел](https://kotlinlang.org/docs/composing-suspending-functions.html#concurrent-using-async).

## Разобранный пример

```kotlin
suspend fun load(): Int = coroutineScope {
    val a = async { delay(200); 20 }
    val b = async { delay(300); 22 }
    a.await() + b.await()
}
```

Результат 42. Два ожидания перекрываются, если оба async созданы до await.

## Как проверить себя в задачах

Открой [задачи](TASKS.md) и запускай каждую отдельно. В журнале смотри на порядок событий, фактический результат и имя потока. Сравнивай только гарантированный порядок: завершение ребёнка до выхода из его scope, результат после await, cleanup до cancelAndJoin. Если поведение удивило, обсудим конкретный вывод в чате.
