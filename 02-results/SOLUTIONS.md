## 02.01 · Получить значение

**Что сделать:** Получи число из уже созданной асинхронной операции. Выведи его вместо начального нуля.

```kotlin
val deferred = async { delay(100); 42 }
val answer = deferred.await()
event("Ответ: $answer")
checkResult("Ответ равен 42", answer == 42)
```

**Почему:** Deferred представляет будущий результат; await возвращает его, при необходимости приостанавливая вызывающую корутину.

**Ожидаемый результат:** Ответ: 42, проверка OK.

## 02.03 · Исправить случайную последовательность

**Что сделать:** В примере две задачи по 150 мс ожидаются сразу после создания. Измени порядок создания и ожидания, чтобы они перекрывались.

```kotlin
val a = async { event("A начало"); delay(150); 20 }
val b = async { event("B начало"); delay(150); 22 }
event("Сумма: ${a.await() + b.await()}")
```

**Почему:** async не ускоряет код, если немедленно ждать каждую операцию перед созданием следующей.

**Ожидаемый результат:** Около 150 мс вместо 300; два старта до получения суммы.

## 02.05 · Собрать экран

**Что сделать:** Реализуй функцию, которая независимо загружает имя «Анна» и число заказов 3, затем возвращает строку «Анна: 3».

```kotlin
suspend fun loadDashboard(): String = coroutineScope {
    val profile = async { delay(100); "Анна" }
    val orders = async { delay(150); 3 }
    "${profile.await()}: ${orders.await()}"
}
val result = loadDashboard()
event(result)
checkResult("Данные объединены", result == "Анна: 3")
```

**Почему:** coroutineScope делает композицию suspend-функцией, не оставляющей скрытых детей.

**Ожидаемый результат:** Анна: 3 и OK.

## 02.06 · Зависимый граф

**Что сделать:** После получения `userId` запустить `fetchProfile(userId)` и `fetchOrders(userId)` одновременно и собрать строку результата. Для этой задачи замени только блок `val summary = coroutineScope { ... }`; остальной код уже есть в файле.

```kotlin
val summary = coroutineScope {
    val profile = async { fetchProfile(userId) }
    val orders = async { fetchOrders(userId) }

```

**Почему:** Профиль и заказы зависят от `userId`, поэтому сначала нужен его результат. После этого запросы независимы: оба `async` создаются до первого `await()`, и ожидания перекрываются. `coroutineScope` возвращает итог после завершения обоих детей.

**Ожидаемый результат:** Сначала получен `userId`, затем стартуют оба запроса; итог `User7: 2` и проверка `OK`.

## 02.07 · Порядок списка

```kotlin
val results = (1..5).map { n -> async { delay((6 - n) * 20L); event("Закончил $n"); n * n } }.awaitAll()
```

## 02.09 · Минимальная цена

**Что сделать:** Смоделировать три магазина: цена 120 через 50 мс, 90 через 100 мс, 110 через 150 мс. Запустить запросы вместе, дождаться всех и вернуть минимальную цену.

```kotlin
suspend fun fetchPrice(price: Int, waitMs: Long): Int {
    delay(waitMs)
    event("Получена цена: $price")
    return price
}

suspend fun bestPrice(): Int = coroutineScope {
    val offers = listOf(120 to 50L, 90 to 100L, 110 to 150L)
    offers.map { (price, waitMs) ->
        async { fetchPrice(price, waitMs) }
    }.awaitAll().min()
}

val result = bestPrice()
event("Лучшая цена: $result")
checkResult("Минимум 90", result == 90)
```

**Почему:** Быстрее всех приходит цена 120, но лучшая — 90. Все `async` создаются до первого ожидания, поэтому задержки перекрываются. `awaitAll()` собирает ответы; `min()` выбирает наименьший только после получения всех.

**Ожидаемый результат:** Три цены, лучшая цена 90 и проверка `OK`.
