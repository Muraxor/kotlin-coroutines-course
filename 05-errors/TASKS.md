# Задачи: Structured concurrency и ошибки

Перед началом прочитай [теорию на русском](THEORY.md) или [теорию на английском](THEORY_EN.md). Выполняй задачи 01–12 по порядку. Каждая находится в своём `TaskNN.kt`. В консоли видны отметки времени, имя потока и результат проверки. Зелёный вывод Gradle означает лишь успешный запуск: проверь также строки `OK` и ожидаемый результат.

Если задача зависла, останови процесс (`Ctrl+C`) и проверь завершение дочерних корутин, Flow или Channel. Для экспериментов с планировщиком не проверяй точные миллисекунды обычных запусков.

## 05.12 · Обязательный источник и отмена соседей

**Уровень:** Самостоятельная реализация механизма корутин; данные, имитация работы, логирование и проверка уже есть. [Открой файл задачи](src/main/kotlin/course/Task12.kt).

Проверь два сценария сборки экрана. В первом профиль и предложения успешны, новости падают: экран должен содержать запасное значение новостей. Во втором падает **обязательный** профиль: экрана быть не должно, а ещё работающие предложения нужно отменить. В каждом сценарии начинай три загрузки одновременно. Не превращай отмену всей операции в запасное значение.

Здесь понадобятся одновременное получение результатов, выбор границ обработки ошибок и отмена дочерней работы из прошлых модулей. Источники, журнал и проверки уже готовы.

**Запуск:**

```bash
./gradlew :05-errors:task12 --console=plain
```

**Что должно быть видно в консоли:** Первый экран `[user=7, news=empty, offers=2]`; второго экрана нет, предложения отменены, источники перекрывались и три строки `OK`.
