# Structured concurrency и ошибки

**Источник:** [официальная документация Kotlin / JetBrains](https://kotlinlang.org/docs/exception-handling.html). Ниже — выборочный учебный перевод и объяснение ключевых положений главы, а не полный текст документации. Примеры адаптированы для задач этого проекта. Чтобы сверить детали поведения, перейди по ссылкам у каждого раздела.

## Ошибка обычного ребёнка

В обычном coroutineScope необработанная ошибка ребёнка отменяет родителя и его остальных детей. При этом finally соседей выполняется. Внешний try/catch вокруг scope получает ошибку после завершения структуры. Ошибка async в обычном scope тоже может запустить отмену ещё до await.

[Официальный раздел](https://kotlinlang.org/docs/exception-handling.html#exception-propagation).

## launch и async

launch предназначен для работы без возвращаемого значения, async — для результата в Deferred. Ошибку корневого launch среда считает необработанной; async сохраняет её для await. Различие не заменяет продуманной обработки в дереве детей. В упражнении всегда помечай, где именно должен быть виден отказ.

[Официальный раздел](https://kotlinlang.org/docs/exception-handling.html#exception-propagation).

## Supervision

supervisorScope позволяет одному ребёнку упасть, не отменяя остальных. Он не превращает ошибку в успешный результат автоматически: обрабатывай её внутри supervised launch или через await у async. Если весь supervisorScope отменён снаружи, его дети тоже отменяются.

[Официальный раздел](https://kotlinlang.org/docs/exception-handling.html#supervision-scope).

## Обработчик исключений

CoroutineExceptionHandler получает необработанные исключения в подходящих корневых или supervised корутинах. К моменту вызова handler корутина уже завершается: через него нельзя восстановить её работу. Для локального fallback удобнее try/catch в нужном ребёнке или Result для конкретного необязательного источника.

[Официальный раздел](https://kotlinlang.org/docs/exception-handling.html#coroutineexceptionhandler).

## Разобранный пример

```kotlin
supervisorScope {
    launch { try { error("сбой") } catch (e: Exception) { println(e.message) } }
    launch { delay(100); println("Второй завершён") }
}
```

Оба сообщения видны; ошибка первого ребёнка обработана локально.

## Как проверить себя в задачах

Открой [задачи](TASKS.md) и запускай каждую отдельно. В журнале смотри на порядок событий, фактический результат и имя потока. Сравнивай только гарантированный порядок: завершение ребёнка до выхода из его scope, результат после await, cleanup до cancelAndJoin. Если поведение удивило, обсудим конкретный вывод в чате.
