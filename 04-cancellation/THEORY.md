# Отмена, таймауты и очистка

**Источник:** [официальная документация Kotlin / JetBrains](https://kotlinlang.org/docs/cancellation-and-timeouts.html). Ниже — выборочный учебный перевод и объяснение ключевых положений главы, а не полный текст документации. Примеры адаптированы для задач этого проекта. Чтобы сверить детали поведения, перейди по ссылкам у каждого раздела.

## Кооперативная отмена

cancel отправляет запрос на отмену. Приостанавливающие функции kotlinx.coroutines обычно проверяют его сами. Чисто вычислительный цикл без приостановок должен проверять currentCoroutineContext().ensureActive(), isActive или вызывать yield. Иначе задача может игнорировать запрос бесконечно долго.

[Официальный раздел](https://kotlinlang.org/docs/cancellation-and-timeouts.html#make-coroutines-react-to-cancellation).

## Отмена детей и ожидание

Отмена родителя распространяется на его дочерние корутины. cancel не означает, что они уже завершили finally. Используй cancelAndJoin, когда нужно дождаться освобождения ресурсов. Событие после него может опираться на то, что дерево завершено.

[Официальный раздел](https://kotlinlang.org/docs/cancellation-and-timeouts.html#cancel-coroutines).

## finally и исключение отмены

Код finally выполняется после успешной работы, ошибки и отмены. CancellationException служит сигналом управления; широкий catch(Exception) должен снова его выбросить. Если для очистки требуется suspend-вызов, небольшой блок withContext(NonCancellable) позволяет ему закончиться; не прячь в него всю работу, иначе отмена теряет смысл.

[Официальный раздел](https://kotlinlang.org/docs/cancellation-and-timeouts.html#run-non-cancelable-blocks).

## Таймаут

withTimeout отменяет блок при истечении времени и сообщает об этом исключением. withTimeoutOrNull для собственного истечения срока возвращает null, что удобно для необязательного результата. Таймаут относится ко всей вложенной операции, включая её детей. В тестах с виртуальным временем задержки можно проверить мгновенно.

[Официальный раздел](https://kotlinlang.org/docs/cancellation-and-timeouts.html#timeout).

## Разобранный пример

```kotlin
val job = launch {
    try { while (true) { delay(100); println("Работаю") } }
    finally { println("Очистка") }
}
delay(250)
job.cancelAndJoin()
println("Остановлено")
```

Очистка появляется до «Остановлено», новые тики после него не появляются.

## Как проверить себя в задачах

Открой [задачи](TASKS.md) и запускай каждую отдельно. В журнале смотри на порядок событий, фактический результат и имя потока. Сравнивай только гарантированный порядок: завершение ребёнка до выхода из его scope, результат после await, cleanup до cancelAndJoin. Если поведение удивило, обсудим конкретный вывод в чате.
