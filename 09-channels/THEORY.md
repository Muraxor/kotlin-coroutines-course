# Channel, очереди и ограничение нагрузки

**Источник:** [официальная документация Kotlin / JetBrains](https://kotlinlang.org/docs/channels.html). Ниже — выборочный учебный перевод и объяснение ключевых положений главы, а не полный текст документации. Примеры адаптированы для задач этого проекта. Чтобы сверить детали поведения, перейди по ссылкам у каждого раздела.

## Передача элементов

Channel соединяет отправителя и получателя. send может приостановиться до доступности места или получателя; receive ждёт элемент. При нескольких workers конкретный элемент получает один из них. Это очередь работы, а не широковещательная рассылка подписчикам как SharedFlow.

[Официальный раздел](https://kotlinlang.org/docs/channels.html#channel-basics).

## Закрытие и перебор

После close нельзя отправлять новые элементы, но получатели могут дочитать уже помещённые в буфер. Цикл for завершается, когда канал закрыт и опустошён. Если producer забыл закрыть канал, такой consumer может ждать бесконечно. При ошибке producer можно закрыть канал с причиной, чтобы consumer увидел отказ.

[Официальный раздел](https://kotlinlang.org/docs/channels.html#closing-and-iteration-over-channels).

## Ёмкость и давление

Канал без буфера синхронизирует встречу send и receive. Ограниченный буфер позволяет отправить несколько элементов заранее, но при заполнении send приостанавливается. Это давление назад не даёт очереди расти без границы. В опыте печатай сообщения до и после send — они покажут точку ожидания.

[Официальный раздел](https://kotlinlang.org/docs/channels.html#buffered-channels).

## Работники и лимит

Несколько workers могут читать один Channel и распределять задания. Число workers ограничивает одновременную обработку; для ограничения произвольных suspend-операций применяй Semaphore.withPermit. Гарантию «ровно один раз» нельзя выводить только из Channel при сбоях: она требует выбранной политики повторов и фиксации результата.

[Официальный раздел](https://kotlinlang.org/docs/channels.html#fan-out).

## Разобранный пример

```kotlin
val queue = Channel<Int>(2)
launch { repeat(3) { queue.send(it) }; queue.close() }
for (item in queue) println(item)
```

Вывод 0,1,2, затем цикл завершается.

## Как проверить себя в задачах

Открой [задачи](TASKS.md) и запускай каждую отдельно. В журнале смотри на порядок событий, фактический результат и имя потока. Сравнивай только гарантированный порядок: завершение ребёнка до выхода из его scope, результат после await, cleanup до cancelAndJoin. Если поведение удивило, обсудим конкретный вывод в чате.
