# Основы: приостановка и конкурентность

**Источник:** [официальная документация Kotlin / JetBrains](https://kotlinlang.org/docs/coroutines-basics.html). Ниже — выборочный учебный перевод и объяснение ключевых положений главы, а не полный текст документации. Примеры адаптированы для задач этого проекта. Чтобы сверить детали поведения, перейди по ссылкам у каждого раздела.

## Корутина и поток

Официальная глава называет корутину приостанавливаемым вычислением. На JVM код всё равно исполняется потоками ОС. Пока одна корутина ожидает ответ, она может уступить поток другой. Это даёт конкурентность; параллельная работа возможна, но зависит от диспетчера и доступных потоков. Не считай число корутин числом потоков.

[Официальный раздел](https://kotlinlang.org/docs/coroutines-basics.html#comparing-coroutines-and-jvm-threads).

## Что делает suspend

suspend разрешает функции приостановиться и позже продолжить выполнение с того же места. Само слово не запускает новый поток и не создаёт дочернюю задачу. Вызвать такую функцию можно из другой suspend-функции или корутины. Если внутри стоит блокирующий Thread.sleep, suspend не исправит блокировку: выбор операции ожидания имеет значение.

[Официальный раздел](https://kotlinlang.org/docs/coroutines-basics.html#suspending-functions).

## Запуск и область жизни

launch запускает дочернюю корутину и возвращает Job. Код родителя после launch продолжает работу, но coroutineScope не завершится, пока не завершатся его дети. Поэтому сообщение после coroutineScope — надёжное место для общего итога. runBlocking нужен главным образом как мост между обычным main и suspend-кодом: он блокирует вызывающий поток до завершения своего тела.

[Официальный раздел](https://kotlinlang.org/docs/coroutines-basics.html#coroutine-scope-and-structured-concurrency).

## delay и порядок событий

delay приостанавливает корутину на заданное время, не занимая поток во время ожидания. Две независимые задержки 200 и 300 мс могут перекрываться; общее время будет близко к большему ожиданию. Порядок сообщений без явной зависимости может меняться. Для точного ожидания задачи используй Job.join, а не «запасной» delay.

[Официальный раздел](https://kotlinlang.org/docs/coroutines-basics.html#create-your-first-coroutines).

## Разобранный пример

```kotlin
suspend fun work(name: String) {
    println("$name: старт")
    delay(200)
    println("$name: готово")
}

fun main() = runBlocking {
    coroutineScope {
        launch { work("A") }
        launch { work("B") }
    }
    println("Оба завершены")
}
```

Два старта до общего завершения; итог после обоих детей.

## Как проверить себя в задачах

Открой [задачи](TASKS.md) и запускай каждую отдельно. В журнале смотри на порядок событий, фактический результат и имя потока. Сравнивай только гарантированный порядок: завершение ребёнка до выхода из его scope, результат после await, cleanup до cancelAndJoin. Если поведение удивило, обсудим конкретный вывод в чате.
