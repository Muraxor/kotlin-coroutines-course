# Решения: Основы: приостановка и конкурентность

Открывай соответствующий пункт после своей попытки. Код ниже вставляется **внутрь `runExercise { ... }`** файла `src/main/kotlin/course/TaskNN.kt`, заменяя заготовку. Общие импорты уже есть. После замены выполни команду задачи и сравни консоль с описанием результата. Это один из возможных вариантов решения.

## 01.01 · Пауза без блокировки

**Что сделать:** Между сообщениями «Начало» и «Конец» добавь приостанавливающее ожидание на 200 мс. Сравни отметки времени.

```kotlin
event("Начало")
delay(200)
event("Конец")
```

**Почему:** delay приостанавливает корутину и освобождает поток. Измеренное время не обязано точно совпадать с аргументом.

**Ожидаемый результат:** «Конец» появляется после «Начало», примерно через 200 мс или позже.

## 01.02 · Родитель продолжает работу

**Что сделать:** В готовом примере запусти медленную работу дочерней корутиной. Сообщение родителя должно появиться до окончания ребёнка.

```kotlin
launch { event("Ребёнок начал"); delay(200); event("Ребёнок закончил") }
event("Родитель продолжает")
```

**Почему:** launch создаёт дочернюю корутину, а вызвавший код продолжает выполнение. Общий scope дождётся ребёнка.

**Ожидаемый результат:** Сообщение родителя раньше «Ребёнок закончил»; порядок двух первых сообщений зависит от запуска.

## 01.03 · Два одновременных ожидания

**Что сделать:** Исправь последовательный пример: обе операции должны начаться до завершения любой из них. Сравни длительность до и после.

```kotlin
coroutineScope {
    launch { event("A начало"); delay(200); event("A конец") }
    launch { event("B начало"); delay(300); event("B конец") }
}
```

**Почему:** Независимые ожидания могут перекрываться даже на одном потоке.

**Ожидаемый результат:** Вместо примерно 500 мс — примерно 300 мс; в журнале два старта перед первым окончанием.

## 01.04 · Дождаться конкретной задачи

**Что сделать:** Замени запасное ожидание на ожидание завершения созданной задачи. Итоговое сообщение должно идти после её окончания.

```kotlin
val job = launch { delay(150); event("Работа готова") }
job.join()
event("Можно использовать результат работы")
```

**Почему:** join связывает ожидание с жизненным циклом Job, а не с угаданной длительностью.

**Ожидаемый результат:** «Работа готова» раньше итогового сообщения; время близко к 150 мс, а не 1000.

## 01.05 · Повторное использование suspend-функции

**Что сделать:** Допиши функцию, которая выводит имя операции до и после паузы. Вызови её из двух дочерних корутин.

```kotlin
suspend fun work(name: String) { event("$name начало"); delay(100); event("$name конец") }
coroutineScope { launch { work("A") }; launch { work("B") } }
```

**Почему:** suspend-функция описывает работу, а launch определяет, когда создать конкурентную задачу.

**Ожидаемый результат:** По одному началу и окончанию для A и B, ожидания перекрываются.

## 01.06 · Блокировка против приостановки

**Что сделать:** На одном потоке сравни две пары задач: сначала обе используют блокирующее ожидание по 100 мс, затем обе — приостанавливающее. Выведи границы обоих опытов.

```kotlin
event("Блокирующий опыт")
coroutineScope { repeat(2) { id -> launch { event("sleep $id начало"); Thread.sleep(100); event("sleep $id конец") } } }
event("Приостанавливающий опыт")
coroutineScope { repeat(2) { id -> launch { event("delay $id начало"); delay(100); event("delay $id конец") } } }
```

**Почему:** На наследуемом однопоточном runBlocking блокирующий sleep задерживает и остальных детей.

**Ожидаемый результат:** В первом опыте второй стартует после первого окончания; во втором два старта до окончания.

## 01.07 · Журнал трёх задач

**Что сделать:** Запусти три задачи с ожиданиями 100, 200 и 300 мс. Для каждой выведи начало и окончание. После scope выведи итог.

```kotlin
coroutineScope {
    listOf(100L, 200L, 300L).forEachIndexed { id, ms ->
        launch { event("$id начало"); delay(ms); event("$id конец") }
    }
}
event("Все три завершены")
```

**Почему:** Причинные зависимости проверяются по событиям. Точный порядок независимых задач не является общей гарантией.

**Ожидаемый результат:** Три начала, затем три окончания; итог после всех окончаний.

## 01.08 · Функция не оставляет фоновой работы

**Что сделать:** Допиши runBatch: она должна запускать трёх детей и возвращаться только после их завершения. Не используй таймер для ожидания детей.

```kotlin
suspend fun runBatch() = coroutineScope {
    repeat(3) { id -> launch { delay(50L * (id + 1)); event("Готов $id") } }
}
runBatch()
event("runBatch вернулась")
```

**Почему:** coroutineScope связывает завершение функции с завершением всех её детей.

**Ожидаемый результат:** Возврат функции отмечен после трёх сообщений «Готов».

## 01.10 · Три загрузки с нуля

**Что сделать:** Смоделируй загрузку трёх файлов. Настоящая сеть не нужна: используй ожидания. Выведи имя, старт, окончание и общий итог.

```kotlin
coroutineScope {
    listOf("a.txt", "b.txt", "c.txt").forEachIndexed { i, name ->
        launch { event("Загрузка $name"); delay(100L + i * 50); event("Получен $name") }
    }
}
event("Загрузки завершены")
```

**Почему:** Структурированная конкурентность выражает группу независимых операций.

**Ожидаемый результат:** Все три старта до первого окончания; итог после получения всех файлов.

## 01.11 · Один поток — несколько корутин

**Что сделать:** Проведи опыт с двумя корутинами на наследуемом потоке. Каждая должна трижды печатать своё имя с паузой. По журналу объясни, выполнялись ли они параллельно.

```kotlin
coroutineScope { repeat(2) { id -> launch { repeat(3) { step -> event("Корутина $id, шаг $step"); delay(50) } } } }
event("Сравни имена потоков у шести сообщений")
```

**Почему:** Чередование задач на одном потоке — конкурентность. По такому журналу нельзя заявить о параллельном исполнении.

**Ожидаемый результат:** Шесть сообщений; один поток может обслужить обе корутины.

## 01.12 · Завтрак с нуля

**Что сделать:** Смоделируй три независимых дела: чай 300 мс, тост 200 мс, яйца 400 мс. Напиши функцию приготовления завтрака, после возврата которой всё готово.

```kotlin
suspend fun breakfast() = coroutineScope {
    listOf("Чай" to 300L, "Тост" to 200L, "Яйца" to 400L).forEach { (name, ms) ->
        launch { event("$name готовится"); delay(ms); event("$name готово") }
    }
}
breakfast()
event("Завтрак подан")
```

**Почему:** Scope задаёт границу операции: результат можно объявить готовым только после завершения её частей.

**Ожидаемый результат:** Завтрак подан после всех трёх блюд; длительность близка к самому долгому делу.
