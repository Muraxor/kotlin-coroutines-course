## 07.01 · Три значения

**Что сделать:** Отправь из flow числа 1,2,3 и выведи их в collect.

```kotlin
flow { emit(1); emit(2); emit(3) }.collect { event("Значение $it") }
```

**Почему:** emit отправляет значение подписчику; collect запускает холодный источник.

**Ожидаемый результат:** Три строки со значениями 1,2,3.

**Почему:** map — промежуточный оператор и выполняется при сборе потока.

## 07.05 · Холодный источник

**Почему:** Обычный Flow холодный: его код исполняется при каждом collect.

## 07.06 · Резервное значение

**Что сделать:** Источник сначала отправляет 1, затем падает. Через catch отправь -1 как запасное значение.


**Почему:** catch обрабатывает upstream-ошибку; ошибку внутри downstream collect он не ловит.

**Ожидаемый результат:** Значения 1 и -1, между ними сообщение об ошибке.

## 07.07 · Буфер

**Что сделать:** Источник выдаёт три значения каждые 20 мс, потребитель обрабатывает по 50 мс. Сравни длительность без buffer и с buffer.

```kotlin
val source=flow { repeat(3) { delay(20);emit(it) } }
val slow:suspend (Int)->Unit={ delay(50);event("Получено $it") }
val a=measureTimeMillis { source.collect(slow) }
val b=measureTimeMillis { source.buffer().collect(slow) }
event("Без буфера: $a мс; с буфером: $b мс")
```

**Почему:** buffer позволяет источнику и потребителю перекрывать работу.

**Ожидаемый результат:** Оба получают 0,1,2; буферная версия обычно быстрее.

## 07.08 · Пропуск и отмена старой обработки

**Что сделать:** На быстром источнике сравни conflate и collectLatest при медленном обработчике. Выведи, что обработано полностью.

```kotlin
val source=flow { repeat(5) { emit(it);delay(20) } }
source.conflate().collect { delay(60);event("conflate $it") }
source.collectLatest { delay(60);event("latest $it") }
```

**Почему:** conflate пропускает промежуточные значения; collectLatest отменяет старый блок обработки.

**Ожидаемый результат:** Обычно видны первый и последний у conflate, последний у collectLatest; детали могут варьировать.

## 07.11 · Отмена коллектора

**Что сделать:** Запусти бесконечный flow, отмени сбор и выведи finally источника.

**Почему:** Отмена сборщика распространяется вверх к источнику.

**Ожидаемый результат:** Несколько чисел, затем finally, затем итог.

## 07.12 · Два потребителя телеметрии

**Что сделать:** Вставь фрагмент вместо TODO в `Task12.kt`, оставив временную переменную `values`.

```kotlin
suspend fun collectMeasurements(): List<Int> = source
    .filter { it >= 0 }
    .distinctUntilChanged()
    .map { it * 2 }
    .catch { emit(-1) }
    .onEach { total.addAndGet(it) }
    .toList()

values = coroutineScope {
    List(2) { async(Dispatchers.Default) { collectMeasurements() } }.awaitAll()
}
```

**Почему:** Холодный поток начинает работу заново для каждой подписки. Два `async` запускают независимые сборы; каждый преобразует события и локально переживает сбой источника. `AtomicInteger` сохраняет общую сумму без потерянных обновлений, а `awaitAll()` собирает результаты в порядке потребителей.

**Ожидаемый результат:** Две подписки, два списка `[2, 4, 10, -1]`, общая сумма `30` и две строки `OK`.
