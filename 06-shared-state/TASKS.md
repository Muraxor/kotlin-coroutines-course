# Задачи: Общие данные: гонки, атомики и Mutex

Перед началом прочитай [теорию на русском](THEORY.md) или [теорию на английском](THEORY_EN.md). Выполняй задачи 01–12 по порядку. Каждая находится в своём `TaskNN.kt`. В консоли видны отметки времени, имя потока и результат проверки. Зелёный вывод Gradle означает лишь успешный запуск: проверь также строки `OK` и ожидаемый результат.

Если задача зависла, останови процесс (`Ctrl+C`) и проверь завершение дочерних корутин, Flow или Channel. Для экспериментов с планировщиком не проверяй точные миллисекунды обычных запусков.

## 06.01 · Найти гонку

**Уровень:** Вставка и исправление. [Открой файл задачи](src/main/kotlin/course/Task01.kt).

Запусти 100 детей по 1000 increment на Default. Выведи фактическое и ожидаемое значение.

**Запуск:**

```bash
./gradlew :06-shared-state:task01 --console=plain
```

**Что должно быть видно в консоли:** Фактический результат может быть меньше 100000; иногда гонка не проявится.

## 06.12 · Бронирование мест

**Уровень:** Самостоятельная реализация механизма корутин; данные, имитация работы, логирование и проверка уже есть. [Открой файл задачи](src/main/kotlin/course/Task12.kt).

Пять клиентов одновременно запрашивают разное число мест при общей вместимости четыре. Обработай каждую заявку целиком: клиент получает **все** запрошенные места или отказ. Сохрани результат каждой заявки в исходном порядке. Остаток нельзя сделать отрицательным, а одно место нельзя продать дважды. В шаблоне уже есть заявки, журнал и проверки; реализуй только безопасную конкурентную обработку.

**Запуск:**

```bash
./gradlew :06-shared-state:task12 --console=plain
```

**Что должно быть видно в консоли:** Пять решений по заявкам; всего продано четыре места, остаток ноль и две строки `OK`. Какие клиенты получат места, зависит от порядка выполнения.
