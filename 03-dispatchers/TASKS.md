# Задачи: Контекст, потоки и диспетчеры

Перед началом прочитай [теорию на русском](THEORY.md) или [теорию на английском](THEORY_EN.md). Выполняй задачи 01–12 по порядку. Каждая находится в своём `TaskNN.kt`. В консоли видны отметки времени, имя потока и результат проверки. Зелёный вывод Gradle означает лишь успешный запуск: проверь также строки `OK` и ожидаемый результат.

Если задача зависла, останови процесс (`Ctrl+C`) и проверь завершение дочерних корутин, Flow или Channel. Для экспериментов с планировщиком не проверяй точные миллисекунды обычных запусков.

## 03.12 · Конвейер файлов с ограничением нагрузки

**Уровень:** Самостоятельная реализация механизма корутин; данные, имитация работы, логирование и проверка уже есть. [Открой файл задачи](src/main/kotlin/course/Task12.kt).

Шесть файлов нужно прочитать и обработать. Готовые `legacyRead` и `analyze` выводят стадии в консоль и ведут счётчики. Построй обработку так, чтобы:

1. Чтения разных файлов могли перекрываться, но одновременно читались не более двух файлов.
2. Блокирующее чтение не занимало вызывающий поток: пока файлы обрабатываются, в консоли должны появляться его тики.
3. Анализ каждого файла выполнялся в контексте для вычислений после окончания его чтения, причём одновременно анализировался только один файл.
4. Анализ готового файла мог идти, пока другие файлы ещё читаются: сначала прочитать всё, а потом всё обработать не подходит.
5. Итоговый список сохранял исходный порядок имён, даже если файлы заканчиваются в другом порядке.

Выбери способ организации корутин и ограничения чтений самостоятельно. В шаблоне уже есть данные, имитация работы, журнал и проверки; допиши только координацию стадий.

**Запуск:**

```bash
./gradlew :03-dispatchers:task12 --console=plain
```

**Что должно быть видно в консоли:** Результат `[(a,9), (bb,10), (ccc,11), (dddd,12), (eeeee,13), (ffffff,14)]`; пики чтения и анализа равны 2 и 1, стадии перекрываются, есть тики вызывающего потока и четыре строки `OK`.
